单 ASIN 市场分析

填入你自己的西柚洞察 MCP Token，输入一个 ASIN 和站点，页面经你自己的 Supabase 中转连西柚洞察拉产品、流量、关键词、竞品和订单数据，按 100 分制算出「能不能尝试上架」的确定性。走 Supabase 时要用下方最新版中转：双头过 JWT 网关 + SSE 流式透传——西柚返回的是流式响应，中转直接透传、网页边读边解析，拿到对应那条数据就结束，不再等整个流关闭而超时。

1 · 西柚洞察 MCP Token

Token 只保存在这台设备的浏览器本地（localStorage），不上传、不共享、不会写进页面代码。换电脑或换浏览器需要重新填一次。填入你自己的 Token 后即可开始分析。本页会自动清洗 Token 格式：粘贴时带了首尾空格、换行、引号，或前面多了 Bearer，都会自动去掉再发送，不会因为多一个空格就被西柚判为查不到。保存 / 测试 / 诊断时下方会显示清洗后 Token 的长度和首尾掩码，方便你核对实际传过去的到底是哪一串（不会显示完整 Token）。

连接方式（连不上时先看这里）

西柚接口 mcp.xydc.com 没有开放浏览器跨域，网页直连会被浏览器拦下。解决办法是走你自己的 Supabase 中转：由 Edge Function 在服务器端转发到西柚，浏览器就不拦了。Token 只发给西柚和你自己的中转，不经过任何第三方公共代理。

换了新 Token 还是 401？多半不是 Token 的问题，是 Supabase 的 JWT 验证在拦。
Supabase Edge Function 默认开着 Verify JWT：它会先检查请求头 Authorization 是不是 Supabase 自己的 JWT。网页原本把西柚 Token 放在这个头里发过去，Supabase 就把它当成自己的 key 来验，验不过直接返回 401——请求根本没到函数、更没到西柚，所以换多少个新西柚 Token 都一样报 401。
本页已改成双头转发（见下方新版函数代码）：Authorization 放 Supabase 的 Publishable / Anon Key 用来过网关，西柚 Token 改放 X-Xydc-Authorization 单独传，函数再把它还原成西柚需要的头转发。这样不用关 Verify JWT 也能通。只改网页或只改函数都不行，两边都要换成新版：① 函数代码换成下方新版并重新 Deploy；② 在下方填入你的 Supabase Publishable Key。
一直转圈 / 超时拿不到数据？这次修的是 SSE 流被卡死，不是 Token。
西柚返回的是 text/event-stream 流式响应，流不会马上关闭。旧版中转用 await res.text() 一次性读完整个流、旧版网页也用 await resp.text() 等整段返回，两边都在等流关闭，结果就是一直等到超时。本页已改成流式：中转用 new Response(res.body, …) 直接透传，网页用流式读取逐条解析 data: 行，拿到带对应 id 的那条 JSON-RPC 就立刻结束。要生效两边都得换新版：① 网页用这一版；② Supabase 函数换成下方最新代码（搜得到 new Response(res.body、搜不到 await res.text() 才算新版）并点 Deploy updates。只换一边，另一边还是会卡住。
两种 401 怎么分（诊断和报错会自动帮你分）：
  • Supabase 拦的 401：返回里带 UNAUTHORIZED_NO_AUTH_HEADER / Invalid JWT / Missing authorization header 这类字样。意思是西柚没收到请求，按上面双头方案处理，或关掉 Verify JWT 后重新部署。
  • 西柚返回的 401 / mcp token credential not found：请求已经过了 Supabase、到了西柚，是西柚按这串字符查不到凭证。本页和新版中转现在都会先自动清洗 Token（去首尾空格、换行、引号，统一 Bearer 前缀，去掉所有空白字符）再发送，所以不要再怀疑是多复制了一个空格——诊断会直接显示清洗后 Token 的长度和首尾掩码，拿它和凭证管理里最新 Token 对长度，对不上就是粘的不是最新那一个或登错了账号。
  • 先看指纹再换 Token：点「诊断连接」后，每条通道结果上方会先列出本次实际发送的 Token 指纹和 Publishable Key 指纹。截图发人排查时只发指纹，不要发完整 Token。

填你自己部署的中转完整地址，页面会直接向这个地址发 MCP 请求，由它转发到西柚。地址里可写 {url} 作为西柚地址占位符；不写占位符就按完整中转地址直接请求。只保存在本机浏览器。还没部署中转时先留空，并按下方说明部署一个。

在 Supabase 项目里找：Project Settings → API Keys，复制 Publishable key（sb_publishable_… 开头，旧项目叫 anon key、eyJ… 开头），就是你部署后示例 curl 里 Authorization: Bearer 后面那一串。不要填 sb_secret_… / service_role key。这个 key 本来就是公开用的，填进来只为了过 Supabase 网关的 JWT 检查；填了之后西柚 Token 会改走 X-Xydc-Authorization 头，不再和它冲突。只保存在本机浏览器，不会写进下载的 HTML。如果你已经用 --no-verify-jwt 关掉了 Verify JWT 并重新部署，这栏可以留空。

为什么不用公共代理：公共代理会经手你的 Token，等于把西柚账号凭证交给陌生服务器，不能用。本页只保留两条路：直连西柚，或走你自己的中转。诊断会逐条试当前通道并告诉你哪条通、哪条不通。

怎么部署 / 更新 Supabase 中转（最新版：双头 + Token 清洗 + SSE 流式透传，约 5 分钟）

已经部署过旧版函数的，必须再更新一次到下面这版——这次改的是超时的根本原因：西柚返回的是 text/event-stream 流式响应（SSE），流不会马上关闭。旧版函数用 await res.text() 想一次性读完整个流，就会一直等流关闭，等到超时也拿不到数据——这就是之前「部署了、Key 也填了，还是连不上 / 一直转圈」的真正卡点。下面这版改成流式透传：直接 return new Response(res.body, …)，不读完、不等待，数据一段一段透传回网页；网页端也已改成流式读取，逐条解析 data: 行，拿到带对应 id 的那条 JSON-RPC 就立刻结束，不等整个流关闭。同时保留上一版的清洗：去掉所有空白和引号、统一成 Bearer + Token 本体 再发给西柚，并同时认 X-Xydc-Authorization 和 X-Xydc-Token 两个头。把函数代码整段换成下面新版，点右下角 Deploy updates 等部署成功，再回本页点诊断——只换网页不换函数，流还是会被旧函数卡住；只换函数不换网页，网页还是会等流关闭。两边都必须是这一版。判断函数是不是新版：搜代码里有没有 new Response(res.body，有才是新版；如果还有 await res.text() 就是旧版，没换成功。

  1. 打开 supabase.com 进你的项目（例如 asin-analysis），左边点 Edge Functions，打开已有的 xydc-proxy（没有就新建，名字填 xydc-proxy，入口文件必须是 index.ts）。
  2. 把代码整段换成下面这段，点 Deploy updates / Deploy 并等它显示成功。代码里不写任何 Token 或 key：西柚 Token 优先从 X-Xydc-Authorization 头读，其次 X-Xydc-Token，都没有时才回退读 Authorization（兼容关掉 Verify JWT 的部署），读到后一律先过 normalizeXydcAuth 清洗再转发；响应一律用 new Response(res.body, …) 流式透传，不要再出现 await res.text()。
import { serve } from "https://deno.land/std@0.168.0/http/server.ts"

const CORS = {
  "Access-Control-Allow-Origin": "*",
  "Access-Control-Allow-Headers": "authorization, apikey, content-type, mcp-protocol-version, mcp-session-id, x-xydc-authorization, x-xydc-token",
  "Access-Control-Allow-Methods": "POST, OPTIONS",
  "Access-Control-Expose-Headers": "mcp-session-id",
}

// 和网页端同一套清洗：去零宽字符、去包裹引号、反复去 Bearer 前缀、去掉全部空白，
// 最后统一拼成 "Bearer " + Token 本体。多一个空格/换行不会再让西柚查不到。
function normalizeXydcAuth(raw: string | null): string {
  let s = (raw || "").replace(/[\u200B-\u200D\uFEFF]/g, "").trim()
  s = s.replace(/^["'`]+/, "").replace(/["'`]+$/, "").trim()
  for (let i = 0; i < 5; i++) {
    const m = s.match(/^bearer\s*:\s*/i) || s.match(/^bearer\s+/i)
    if (!m) break
    s = s.slice(m[0].length).trim()
  }
  s = s.replace(/\s+/g, "").replace(/^["'`]+/, "").replace(/["'`]+$/, "")
  return s ? `Bearer ${s}` : ""
}

serve(async (req) => {
  if (req.method === "OPTIONS") {
    return new Response(null, { headers: CORS })
  }
  const rawAuth = req.headers.get("x-xydc-authorization") || req.headers.get("x-xydc-token") || req.headers.get("authorization") || ""
  const auth = normalizeXydcAuth(rawAuth)
  const body = await req.text()
  const res = await fetch("https://mcp.xydc.com/mcp", {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Accept": "application/json, text/event-stream",
      "Authorization": auth,
      "MCP-Protocol-Version": req.headers.get("mcp-protocol-version") || "2025-11-25",
      ...(req.headers.get("mcp-session-id") ? { "Mcp-Session-Id": req.headers.get("mcp-session-id")! } : {}),
    },
    body,
  })
  // ★ 流式透传（本次根治点）：西柚返回的是 text/event-stream 流式响应，
  // 流不会马上关闭。绝不能用 await res.text() 一次性读完——那会一直等流
  // 关闭，西柚不关流就一直等到超时，网页永远拿不到数据。
  // 直接把 res.body 透传回去，浏览器端边读边解析，拿到对应 id 的那条就结束。
  const headers = new Headers(CORS)
  headers.set("Content-Type", res.headers.get("content-type") || "application/json")
  const sid = res.headers.get("mcp-session-id")
  if (sid) headers.set("Mcp-Session-Id", sid)
  return new Response(res.body, { status: res.status, headers })
})
  1. 路线 A（推荐，不用命令行）：保持 Verify JWT 开着。回本页上方填三样：西柚 Token、中转地址 https://你的项目ID.supabase.co/functions/v1/xydc-proxy、Supabase Publishable Key；通道选「只走我自己的中转地址」，点「诊断连接」。页面发请求时 Authorization 带的是 Supabase 的 key（过网关），西柚 Token 走单独的头（到西柚），两边互不冲突。
  2. 路线 B（二选一）：关掉 Verify JWT。网页编辑器里部署时如果有 Verify JWT 开关就关掉；没有开关就用命令行重新部署：supabase functions deploy xydc-proxy --no-verify-jwt。走这条路线时本页的 Publishable Key 可以留空，页面会直接用 Authorization 发西柚 Token。注意：只在网页里改代码、没带 --no-verify-jwt 重新部署，Verify JWT 还是开着的，还是会拦。
  3. 不要直接在浏览器地址栏打开中转地址测通不通：那样不带任何头，Supabase 必然返回 Missing authorization header，那是正常的。只能回本页点「诊断连接 / 测试连接」测。
  4. Cloudflare Worker 同理：用同样的转发逻辑（优先读 X-Xydc-Authorization）部署，把 Worker 地址填进来，Publishable Key 留空即可。

导出 HTML 文件 · 打不开怎么办

是的，这个页面本身就是一个 HTML 文件，文件名必须是 index.html，只有一个文件，不需要其他文件。点下面按钮就能下载一份干净的 index.html，可以双击用浏览器打开，也可以传到 GitHub / Vercel 部署。

下载后请确认文件名结尾是 .html，不是 .txt，也不是没有后缀。

双击打不开 / 打开是乱码或代码，按顺序查这 4 点：

  1. 文件名不对（最常见）：如果文件叫 index、index.html.txt 或 单ASIN市场分析，双击就打不开。把它重命名为 index.html。Windows 要先在文件资源管理器点「查看 → 显示 → 文件扩展名」，才能看到并改对后缀。
  2. 打开方式不对：不要用记事本、Word 打开。右键文件 → 打开方式 → 选择 Chrome 或 Edge。打开后地址栏是 file:///…/index.html，看到和本页一样的界面就是打开成功了。
  3. 在 GitHub 里点开看到的是代码：这是正常的。GitHub 只是存文件的地方，点 index.html 只会显示代码，不会变成网站。真正的网站地址是 Vercel 给的 https://xxx.vercel.app，要用那个链接打开。
  4. 点「测试连接 / 开始分析」报连不上或 401：先看诊断把 401 分成哪一种。带 Invalid JWT / UNAUTHORIZED 字样的是 Supabase 网关的 Verify JWT 在拦（西柚 Token 被当成 Supabase 的 key），不是 Token 失效：按 Token 区的新版双头方案更新函数代码、填入 Supabase Publishable Key，或关掉 Verify JWT 后用 --no-verify-jwt 重新部署。只有诊断明确说是「西柚返回 401」时，才需要换西柚 Token。不要用网上公共代理转发 Token，等于把凭证交给陌生服务器。

手机上：不要直接在微信里点文件预览，先下载后用 Chrome / Safari 打开，或直接打开 Vercel 的 https 链接使用。
